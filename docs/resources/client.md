# rauthy_client (Resource)

An OIDC client in Rauthy.

Creating one takes two API calls: `POST /clients` accepts only the id, name, confidentiality and the redirect URIs and silently ignores everything else, so the provider immediately follows it with `PUT /clients/{id}` carrying the full configuration.

A confidential client's secret is generated by Rauthy and cannot be supplied from outside, which is why `secret` is a read-only attribute rather than something you set.

## Attributes that are optional and computed

Most settings on this resource are both optional and computed, and that has a consequence worth knowing before you rely on it.

`PUT /clients/{id}` is a full replacement: Rauthy requires a concrete value for `enabled`, `flows_enabled`, `scopes`, `default_scopes`, both signing algorithms, both lifetimes and `force_mfa` on every update, and rejects a request that omits any of them. The provider therefore always has to send something. When you do not configure an attribute, it sends back whatever Rauthy currently has — the defaults Rauthy chose when the client was created.

The cost is that **removing such an attribute from your configuration does not revert it**. Terraform keeps the last applied value and the provider keeps sending it, so the setting stays where you left it. To change one of these settings, set it explicitly; there is no way to say "go back to the default" other than writing the default down.

The alternative — the provider carrying its own hardcoded defaults — was rejected deliberately: those defaults would drift away from Rauthy's on the next upgrade and silently rewrite clients nobody meant to touch.

## Example Usage

```terraform
# A confidential client: Rauthy generates the secret, the provider reads it back.
resource "rauthy_client" "backend" {
  id            = "example-backend"
  name          = "Example Backend"
  confidential  = true
  redirect_uris = ["https://app.example.com/oidc/callback"]

  post_logout_redirect_uris = ["https://app.example.com/"]
  allowed_origins           = ["https://app.example.com"]

  flows_enabled         = ["authorization_code", "refresh_token"]
  scopes                = ["openid", "profile", "email"]
  default_scopes        = ["openid"]
  access_token_alg      = "EdDSA"
  id_token_alg          = "EdDSA"
  auth_code_lifetime    = 60
  access_token_lifetime = 600
  force_mfa             = false

  # Change this value to rotate the secret. The old one keeps working for
  # another 6 hours so consumers can catch up.
  secret_rotation_trigger    = "2026-01-01"
  secret_cache_current_hours = 6
}

# The secret is computed and sensitive; wiring it anywhere is up to you.
output "backend_client_secret" {
  value     = rauthy_client.backend.secret
  sensitive = true
}

# A public single-page app: no secret, and Rauthy requires S256 PKCE from it.
resource "rauthy_client" "spa" {
  id            = "example-spa"
  name          = "Example SPA"
  confidential  = false
  redirect_uris = ["https://spa.example.com/callback"]

  allowed_origins = ["https://spa.example.com"]
  flows_enabled   = ["authorization_code", "refresh_token"]
  scopes          = ["openid", "profile"]
  default_scopes  = ["openid"]
}
```

## Import

Import is supported using the following syntax:

```shell
# Clients are imported by their client id. The secret is read back from Rauthy,
# but secret_rotation_trigger and secret_cache_current_hours exist only in
# Terraform and stay unset after an import.
terraform import rauthy_client.backend example-backend
```
