# rauthy_pam_user (Resource)

Manages a POSIX account in Rauthy's PAM subsystem, the part of Rauthy that acts as an authentication source for hosts and SSH logins.

This resource does not create an identity — it attaches POSIX attributes to a Rauthy user that already exists, matched by email. The email must belong to an existing `rauthy_user` that no other PAM user has claimed yet, or Rauthy answers with a bare `404 no rows returned`.

SSH keys are deliberately not managed here. Rauthy only lets the account holder add them, through `/pam/users/self/authorized_keys`; an API key cannot, so they are runtime state.

Requires these API key rights: `Pam` read, create, update, delete.

## Example Usage

```terraform
// A PAM user attaches POSIX attributes to a Rauthy identity that already
// exists; it never creates one. The email is the link between the two.
resource "rauthy_user" "alice" {
  email       = "alice@example.com"
  given_name  = "Alice"
  family_name = "Anderson"
}

resource "rauthy_pam_group" "developers" {
  name = "developers"
  typ  = "generic"
}

resource "rauthy_pam_user" "alice" {
  username = "alice"
  email    = rauthy_user.alice.email

  shell    = "/bin/zsh"
  home_dir = "/home/alice"

  // The complete membership set. Rauthy replaces it wholesale on every write,
  // so an omitted group is a removed group — including the personal group it
  // created for this account, which cannot be listed here because its gid is
  // an attribute of this very resource. Leave `groups` out entirely to keep
  // whatever Rauthy set up instead.
  groups = [
    {
      gid   = rauthy_pam_group.developers.id
      wheel = true
    },
  ]
}
```

## Schema

### Required

- `email` (String) Email of the existing Rauthy user this account belongs to. As with the username, it cannot be changed in place.
- `username` (String) POSIX login name. Rauthy offers no way to change it afterwards, so a different name replaces the account.

### Optional

- `groups` (Attributes Set) Supplementary group memberships, as the complete set. Rauthy replaces the whole membership list on every write, and it makes no exception for the personal group in `gid` — declaring `groups = []` really does leave the account in no group at all. Leave the attribute out to keep whatever Rauthy set up at creation. (see [below for nested schema](#nestedatt--groups))
- `home_dir` (String) Home directory. Rauthy defaults a new account to `/home/<username>`.
- `shell` (String) Login shell. Rauthy defaults a new account to `/bin/bash` and does not check that the value is a path, let alone that it exists on any host.

### Read-Only

- `gid` (Number) Numeric gid of the personal group Rauthy creates alongside the account. It is not choosable, and it disappears with the account.
- `id` (Number) Numeric uid Rauthy assigned to the account.

### Nested Schema for `groups`

Required:

- `gid` (Number) Numeric gid of the group, normally `rauthy_pam_group.<name>.id`.

Optional:

- `wheel` (Boolean) Whether membership in this group grants sudo on the hosts that use it.

## Import

Import is supported using the following syntax:

```shell
# PAM users are imported by their numeric uid, not by username.
terraform import rauthy_pam_user.alice 100000
```
